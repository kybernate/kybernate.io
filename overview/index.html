GPU inference on Kubernetes

Let models sleep.
Keep GPUs busy.

Kybernate saves an idle AI model’s running state so another model can use the same NVIDIA GPU. When the sleeping model gets a request, it picks up where it left off and skips a full cold start.

Explore the model states

Hot / GPU memory

Ready to answer.

A model serving requests lives in GPU memory (VRAM). Its weights are loaded, its kernels are ready, and vLLM can start generating an answer as soon as a request arrives.

GPU In use by this model

Warm / Host RAM

Make room for another model.

When requests stop, NVIDIA’s cuda-checkpoint saves the model’s GPU state in the node’s main memory. Another model can use the GPU while the first one sleeps.

GPU Available to other models

In one RTX 3060 test, a workload with 2 GB in GPU memory resumed from RAM in about 1.2 seconds.

Cold / Local SSD

Save it for later.

For a longer pause, CRIU saves the container’s processes to local storage alongside the GPU state. This frees host RAM, too. On the next request, the proxy can queue it while Kybernate restores the initialized model.

GPU + host RAM Available to other models
